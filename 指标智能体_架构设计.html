1. 设计目标与约束

1.1 设计目标

  1. 可工程化：替代 Dify 拖拽，建立可测试、可灰度、可重放的 Agent 系统
  2. 降本提速：模型分流将单次推导成本下降 ≥ 60%，延迟下降 ≥ 40%
  3. 突破大 JSON 瓶颈：支持 10000 张表/单次任务无 Token 上限与注意力稀释
  4. 离线可部署：内网无外网虚机一键起服
  5. 可观测可审计：每一次 LLM 调用、检索、推导步骤可追溯、可脱敏

1.2 关键约束

维度约束
部署单机虚机起步，无外网，离线包交付
QPS≤ 100（含峰值）
知识库规模< 1000 文档，< 5 万 chunk
数据敏感性必须 PII 脱敏 + 全审计
模型采购分三阶段：CPU 验证 → API 选型 → GPU 自部署
主语言Python（AI 核心）+ Java（业务接入）

4.1 LLM Router（核心可切换层）

图 4-1 LLM Router 三模式切换
class LLMRouter:
    def __init__(self, mode: Literal["api", "vllm", "llama_cpp"]):
        self.mode = mode
        self.heavy = {
            "api":      ChatOpenAI(base_url="https://dashscope.../v1", model="qwen-plus"),
            "vllm":     ChatOpenAI(base_url="http://vllm:8000/v1", model="Qwen2.5-32B-Instruct-AWQ"),
            "llama_cpp":ChatLlamaCpp(model_path="./models/qwen2.5-32b-q4.gguf"),
        }
        self.fast = {
            "api":      ChatOpenAI(model="qwen-turbo"),
            "vllm":     ChatOpenAI(base_url="http://vllm-7b:8000/v1", model="Qwen2.5-7B-Instruct"),
            "llama_cpp":ChatLlamaCpp(model_path="./models/qwen2.5-7b-q4.gguf"),
        }

    def chat(self, level: Literal["fast","heavy"], messages, schema=None):
        backend = self.fast[self.mode] if level == "fast" else self.heavy[self.mode]
        if schema:
            return backend.with_structured_output(schema).invoke(messages)
        return backend.invoke(messages)

限流与背压

维度策略
全局 QPSAPISIX 全局 100 QPS
单用户 QPS10 QPS（防滥用）
Agent 并发Celery prefetch 4 + max-concurrency 8
模型调用LLM Router 内置 token bucket（按 TPM）
队列长度Redis 队列阈值 1000，超过返回 503

故障与降级

故障降级
主推导模型不可用fallback 到 7B 出兜底版（标记低置信度）
RAG 检索超时跳过 RAG，纯模型先验输出
Embedding 服务挂全文检索单独走 BM25
PG 主库挂读走只读副本；写降级离线 + 重试
任务超时LangGraph checkpoint 保留；下次续跑

6.1 审计三表

-- 请求级
CREATE TABLE audit.request_log (
  id BIGSERIAL PRIMARY KEY,
  trace_id UUID NOT NULL,
  user_id VARCHAR(64),
  endpoint VARCHAR(128),
  payload_hash VARCHAR(64),
  pii_findings JSONB,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
-- LLM 调用级
CREATE TABLE audit.llm_call (
  id BIGSERIAL PRIMARY KEY,
  trace_id UUID NOT NULL,
  model VARCHAR(64),
  prompt_tokens INT,
  completion_tokens INT,
  latency_ms INT,
  status VARCHAR(16),
  created_at TIMESTAMPTZ DEFAULT NOW()
);
-- 工具调用级
CREATE TABLE audit.tool_call (
  id BIGSERIAL PRIMARY KEY,
  trace_id UUID NOT NULL,
  tool_name VARCHAR(64),
  args JSONB,
  result_hash VARCHAR(64),
  latency_ms INT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

8.2 风险与对策

风险影响概率对策
32B 模型推导精度不达预期高中API 阶段并行测 72B；预留升级路径
大 JSON 分类落入"杂项域"中中设兜底域 + 业务复核环节
pgvector 规模性能拐点低低监控 P95；达 200 万切 Milvus
离线模型版本管理混乱中中SHA256 + 版本号；模型仓
Java 团队 Python 上手慢中中脚手架 + 培训；前两个月 AI 团队主导
Web 搜索内网不可用低高替换为内部资料库工具 / 关闭
Phoenix/OTel 数据量大低中采样率 10%，关键链路 100%
