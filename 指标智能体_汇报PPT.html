索引召回QPS

最低环境配置（三阶段）

阶段 1：CPU 验证

0~2 周 · 跑通功能链路

  • llama.cpp + GGUF Q4
  • 32C / 64G 虚机
  • 7B Q4 ≈ 4.5GB
  • 32B Q4 ≈ 19GB
  • 不追性能

阶段 2：API 验证

2~6 周 · 选型对比

  • 临时联网白名单
  • 5 个候选：7B/14B/32B/72B/DeepSeek-V2.5
  • 预算：2000~4000 元
  • Phoenix 全程 Trace
  • 准/快/便宜 三维评估

阶段 3：GPU 生产

6 周后 · 上线

  • vLLM + 32B-AWQ
  • 1×A100 40G 或 L20 48G
  • 64C 256G + 2T NVMe
  • guided_json 上线
  • SLO P95 ≤ 5s
离线包总量 ~70GB：Docker 镜像 15GB + Python wheel 3GB + 模型权重 50GB + 配置/脚本，一块 128GB U 盘可拷入内网。

风险与对策 · 致谢
风险影响对策
32B 模型推导精度不达预期高API 阶段并行测 72B；预留升级路径
大 JSON 分类落入"杂项域"中设兜底域 + 业务复核环节
pgvector 性能拐点低监控 P95；规模达 200 万切 Milvus
离线模型版本管理混乱中SHA256 校验 + 版本号 + 模型仓
Java 团队 Python 上手慢中脚手架 + 培训；前两月 AI 团队主导
Web 搜索内网不可用低替换为内部资料库工具 / 关闭
Phoenix/OTel 数据量过大低采样率 10%；关键链路 100%
整体策略：路径 A → CPU 验证（W2）→ API 选型（W4）→ 性能达标（W6）→ 离线包（W7）→ UAT（W8）→ GPU 上线（W10）。
关键收益：成本 ↓60% · 延迟 ↓40% · 支持万张表 · 工程化达标。
