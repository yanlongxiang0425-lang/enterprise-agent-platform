# 企业级生产化改造_第四阶段报告

检查时间：2026-05-18

## 1. 阶段结论

第四阶段完成“通用智能体底座命名与后台执行入口”改造。

项目对外命名从单一物料智能体升级为 `enterprise-agent-platform`，新增通用底座包 `agent_platform`。现有物料分类能力作为首个业务智能体 `material-classification` 注册到底座中。旧的 `material_agent` 包、`material-agent` CLI 和 `/api/material-agent/...` 路由继续保留兼容，避免破坏当前样例验证和已有调用。

## 2. 命名规范调整

| 层级 | 新命名 | 说明 |
|---|---|---|
| 项目名 | `enterprise-agent-platform` | 企业级通用智能体平台，适合后续挂多个智能体 |
| 通用底座包 | `agent_platform` | Agent 注册表、平台公共能力、未来通用 executor/observability/guardrails |
| 首个业务智能体 | `material-classification` | 物料分类补全 Agent |
| 兼容包 | `material_agent` | 保留现有物料智能体实现，避免大规模迁移风险 |
| 新 CLI | `agent-platform` | 平台级 CLI 入口 |
| 兼容 CLI | `material-agent` | 保留旧入口 |
| 新 API 前缀 | `/api/agent-platform/...` | 平台级生产接口 |
| 兼容 API 前缀 | `/api/material-agent/...` | 保留旧接口 |
| FastAPI 标题 | `Enterprise Agent Platform` | 对外服务名称 |
| Docker 镜像 | `enterprise-agent-platform:0.4.0` | 容器镜像命名 |

## 4. 新增平台级 API

| 接口 | 说明 |
|---|---|
| `GET /api/agent-platform/agents` | 查询已注册智能体 |
| `POST /api/agent-platform/tasks/material-classification/default` | 创建默认物料分类任务 |
| `POST /api/agent-platform/tasks/material-classification` | 创建自定义物料分类任务 |
| `GET /api/agent-platform/tasks/{task_id}` | 查询任务 |
| `GET /api/agent-platform/tasks/{task_id}/events` | 查询任务事件 |
| `POST /api/agent-platform/tasks/{task_id}/submit` | 提交后台执行器 |
| `POST /api/agent-platform/tasks/{task_id}/run` | 同步执行任务，调试/本地验证用 |

## 8. 后续建议

第五阶段建议继续做生产执行层增强：

1. 为任务增加锁和重复提交保护。
2. 增加取消、重试和最大重试次数。
3. 将 `ThreadPoolTaskExecutor` 替换为可选 Redis/RQ/Celery executor。
4. 把通用任务服务从 `material_agent` 逐步迁移到 `agent_platform`，业务 Agent 只保留自身处理逻辑。
5. 增加 `AgentHandler` 协议，不同智能体通过 handler 执行各自任务。
