# 两个智能体需求实现要点总结

## 1. 总体目标

建设一个**公共底层智能体平台**，不是为单个需求单独开发一套系统。平台需要同时支撑两个业务 Agent：

1. **指标体系构建 Agent**
2. **基于物料分类/物料知识库的补全 Agent**

公共底座能力包括：

- Agent Runtime
- LangGraph 状态机编排
- Tool / MCP / Skill 能力体系
- Model Gateway 模型路由
- RAG 知识库服务
- Excel/Word 等文件解析
- PostgreSQL + pgvector 存储
- Redis 队列与缓存
- 短期记忆与长期记忆
- 审计、脱敏、可观测、评测
- 内网离线部署能力

---

## 2. 需求一：指标体系构建 Agent

### 2.1 业务目标

输入表结构、业务说明、Excel/Word 文档或 Prompt，自动生成一套结构化的指标体系。

### 2.2 输入

- 表结构 JSON / table_json
- Excel 表结构或字段说明
- Word 指标口径或业务说明
- 用户 Prompt
- 业务域上下文

### 2.3 输出

标准化指标体系 JSON，包含：

- 业务域
- 指标名称
- 指标定义
- 统计口径
- 维度
- 度量
- 计算逻辑
- 依赖字段
- SQL 建议
- 可行性检查结果
- 人工确认状态

### 2.4 核心处理流程

1. **输入归一化**
   - 将 table_json、Excel、Word、Prompt 统一转成 TaskContext。

2. **Schema 瘦身**
   - 不能把上千/上万张表拼成一个大 JSON 直接喂给模型。
   - 只保留：
     - table
     - column
     - comment
     - dtype
     - sample
     - key hints
   - 按库、表、业务域分批处理。

3. **业务域分类**
   - 使用小模型做业务域分类。
   - 辅助使用字段字典、表字段语义、指标知识库 RAG。

4. **指标知识检索**
   - 从指标口径文档、历史指标体系、行业指标规则中检索相关上下文。
   - 使用 pgvector + metadata filter + rerank。

5. **指标推导**
   - 使用主推理模型生成指标候选。
   - 按业务域并行推导。
   - 输出必须符合 JSON Schema。

6. **可行性复评**
   - 检查字段是否存在。
   - 检查口径是否冲突。
   - 检查 SQL 建议是否可执行。
   - 检查维度/度量关系是否合理。

7. **人工确认**
   - 低置信度指标、冲突口径、缺失字段进入 HITL。
   - 人工确认后进入长期记忆和评测样本。

8. **结果输出**
   - 输出 metric_system_json。
   - 记录 metric_artifacts。
   - 保存审计与执行链路。

## 3. 需求二：基于物料分类/物料知识库的补全 Agent

### 3.1 业务目标

给定物料知识库 Excel，里面包含物料基本信息、物料分类、属性字段等数据。用户上传待补全 Excel，可能只有物料 ID、物料分类或少量字段，系统需要根据知识库批量补全目标 Excel 中的属性字段。

这不是传统“离线 RAG 问答”需求，主路径应是**结构化精确查询 + 批量字段回填**。RAG/LLM 只作为辅助能力。

### 3.2 输入

- 物料知识库 Excel
- 待补全 Excel
- 物料 ID / 物料编码 / 物料分类 / 其他关键字段
- 目标补全字段配置
- 字段别名配置

### 3.3 输出

- 补全后的 Excel 文件
- 异常 sheet
- 差异报告
- 未命中记录
- 多命中记录
- 冲突字段记录
- 补全统计：
  - 总行数
  - 命中行数
  - 未命中行数
  - 冲突行数
  - 补全字段数
- 审计日志

### 3.4 核心处理流程

1. **知识库导入**
   - 解析物料知识库 Excel。
   - 建立：
     - material_master_rows
     - material_attributes
     - material_row_snapshot
     - field_dictionary
   - 保留 row_json，用于动态字段回填。

2. **待补全 Excel 上传**
   - 解析 sheet、表头、行号、字段。
   - 识别物料 ID 列或分类列。
   - 支持字段别名：
     - 物料ID
     - 物料编码
     - 物料号
     - material_id

3. **字段校验**
   - 检查物料 ID 是否为空。
   - 检查重复 ID。
   - 检查格式异常。
   - 检查目标字段是否存在映射。

4. **知识库精确匹配**
   - 主路径使用 PostgreSQL 精确查询。
   - material_id / category_id 建 B-tree 索引。
   - row_json 用 JSONB 保存整行属性。
   - 不应把该场景设计成向量召回主路径。

5. **属性字段补全**
   - 根据匹配到的 row_json 或属性表回填目标字段。
   - 支持策略：
     - 只填空值
     - 覆盖已有值
     - 保留原值并生成差异列
   - 记录字段来源、知识库版本、匹配置信度。

6. **异常处理**
   - 未命中：生成异常记录。
   - 多命中：进入人工确认。
   - 字段冲突：生成 diff_json。
   - 低置信度匹配：进入 HITL。

7. **导出结果**
   - 输出补全后的 Excel。
   - 增加异常 sheet。
   - 增加补全统计 sheet。
   - 保存 enrichment_results。

8. **反馈闭环**
   - 人工确认后的字段别名、分类映射、异常样本写入长期记忆。
   - 作为后续补全和评测样本。

## 5. 模型切换设计

### 5.1 三类模型

1. **路由/分类模型**
   - 用于：
     - 业务域分类
     - 意图识别
     - 字段别名判断
     - 物料分类辅助
   - 推荐小模型，如 Qwen 7B/14B。

2. **主推理模型**
   - 用于：
     - 指标推导
     - 口径解释
     - 异常说明
     - 补全报告摘要
   - 推荐 Qwen 14B/32B 或 API 候选模型。

3. **Embedding / Rerank 模型**
   - Embedding：bge-m3
   - Rerank：bge-reranker-v2-m3
   - 用于知识入库、语义召回和重排。

### 5.2 三种部署模式

1. **CPU Local**
   - llama.cpp + GGUF
   - 用于前期功能验证
   - 不承诺推理性能

2. **API Remote**
   - 内部或云模型 API
   - 用于模型效果选型和成本评估

3. **GPU vLLM**
   - vLLM OpenAI Compatible Server
   - 用于生产推理
   - 模型确认后再采购 GPU

### 5.3 切换方式

通过 Model Gateway 统一路由：

```text
LLM_ROUTER_MODE=cpu_local
LLM_ROUTER_MODE=api_remote
LLM_ROUTER_MODE=gpu_vllm
```

上层 LangGraph Node 不直接绑定具体模型，只声明任务类型：

```text
task_type = classify / route / alias / reason / generate / embedding / rerank
```

## 6. RAG 知识库设计

### 6.1 RAG 使用边界

RAG 是底层能力，不是第三个业务需求。

### 6.2 指标 Agent 中的 RAG

用于检索：

- 指标口径
- 维度定义
- 历史指标体系
- 行业指标规则
- 表字段语义说明

### 6.3 物料补全 Agent 中的 RAG

主路径不使用 RAG。

RAG 仅用于：

- 字段别名解释
- 物料分类规则检索
- 模糊字段映射
- 异常说明生成
- 低置信度候选辅助

### 6.4 Chunk 分块规则

| 知识类型 | 分块规则 |
|---|---|
| 指标口径 Word/PDF | 标题层级 + 语义段落 |
| 指标/字段 Excel | 结构化表先入 schema/field 表，必要时按行生成 chunk |
| 物料分类规则 Excel | 分类编码/属性规则按行或规则组分块 |
| 物料主数据 Excel | 主路径入 master_rows，按物料 ID 精确查询；仅描述字段可生成 chunk |
| 普通文本/Markdown | 300-800 tokens，50-100 overlap |

### 6.5 检索流程

1. Query 理解
2. metadata filter
3. pgvector topK 召回
4. rerank 重排
5. 权限过滤
6. 组装上下文
7. 返回 source_id、chunk_id、page/row、score

## 7. LangGraph 设计

### 7.1 GraphState 核心字段

```python
class GraphState:
    run_id: str
    agent_type: str
    task_context: dict
    security_context: dict
    plan: list
    memory: dict
    tool_results: dict
    retrieval_context: dict
    model_outputs: list
    validation_errors: list
    human_feedback: list
    final_result: dict
```

### 7.2 公共节点

```text
input_adapter
policy_guard
planner
tool_executor
validator
audit_writer
```

### 7.3 指标体系构建 Agent 节点

```text
schema_slimmer
domain_classifier
metric_retriever
metric_generator
feasibility_checker
hitl_review
```

### 7.4 物料分类补全 Agent 节点

```text
parse_excel
detect_key
exact_lookup
fill_attrs
diff_validate
export_report
```

### 7.5 状态流转

```text
INIT
  -> INPUT_VALIDATED
  -> PLANNED
  -> RUNNING
  -> WAIT_HITL
  -> VALIDATING
  -> COMPLETED
```

异常状态：

```text
RUNNING -> RETRYING -> RUNNING
RUNNING -> FAILED
VALIDATING -> RETRYING
WAIT_HITL -> RUNNING
```

## 8. Memory 设计

### 8.1 短期记忆

存储位置：

- LangGraph Checkpoint
- Redis
- agent_runs.task_context

保存内容：

- 当前任务输入
- 中间计划
- 工具结果
- 检索上下文
- 模型输出
- 待确认项
- 错误信息

使用场景：

- 节点重试
- 人工确认后继续执行
- SSE 状态展示
- 任务恢复

生命周期：

- run 结束后归档
- 敏感字段脱敏

### 8.2 长期记忆

存储位置：

- PostgreSQL field_dictionary
- metric_artifacts
- evaluation_cases
- historical_feedback
- rag_chunks

保存内容：

- 人工确认过的字段别名
- 指标口径
- 物料分类映射
- 物料字段映射
- 错误样本
- 评测样本

使用场景：

- 后续字段映射
- 指标推导
- 物料分类补全
- 回归评测

写入规则：

- 只写人工确认结果
- 高置信结果可候选写入
- 必须版本化
- 必须可回滚

## 11. PostgreSQL + pgvector 是否足够

当前阶段建议使用 PostgreSQL + pgvector，不优先引入 Elasticsearch。

原因：

- 指标知识库和物料分类规则规模不大。
- 物料补全主路径是结构化精确查询，不是全文搜索。
- PostgreSQL 支持：
  - B-tree
  - JSONB GIN
  - pg_trgm
  - full-text
  - pgvector HNSW
- 减少组件数量，适合内网单机虚机部署。

后续只有出现以下情况再考虑 Elasticsearch / OpenSearch：

- 大规模全文检索
- 高级中文分词
- 高亮展示
- 多字段复杂聚合
- 高并发搜索
- PostgreSQL 查询性能瓶颈

## 12. 最低环境配置

### CPU 最小验证

```text
16C / 64GB RAM / 500GB SSD
```

可验证：

- Agent API
- LangGraph Runtime
- Tool 调用
- RAG 入库
- 物料补全
- 审计
- CPU 慢速模型验证

### CPU 推荐验证

```text
32C / 128GB RAM / 1TB SSD
```

可验证：

- 几万字段
- 批量 Excel
- 非模型接口 100 QPS
- 多 worker 并发

### GPU 生产起步

```text
32C / 128GB RAM / 2TB SSD
+ L20 48GB 或 A100 40GB
```

用于：

- 14B/32B 量化模型推理
- embedding/rerank 服务
- vLLM 高吞吐推理
