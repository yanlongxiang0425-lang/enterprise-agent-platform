# 企业级生产化改造_第二阶段报告

检查时间：2026-05-18

## 1. 阶段结论

第二阶段已完成“任务化与持久化骨架”改造。

当前服务不再只依赖同步 CLI 或同步 HTTP 调用，可以按生产服务常见方式创建任务、记录任务状态、执行任务、查询任务结果。本阶段暂时使用本地 JSON 文件仓储模拟数据库任务表，后续可替换为 PostgreSQL 表，不影响上层 API 和任务服务。

知识库导入、文件上传、对象存储、数据库落库等能力暂不在本阶段展开，后续单独优化。

## 3. 当前任务流

```text
创建任务
  -> 写入 task JSON：pending
  -> 返回 task_id

执行任务
  -> 读取 task
  -> 状态更新为 running
  -> 调用现有 MaterialCompletionEngine
  -> 成功：succeeded + metrics + output_files
  -> 失败：failed + error

查询任务
  -> 按 task_id 读取 task JSON
  -> 返回状态、输入文件、输出文件、参数、指标、错误信息
```

## 4. 任务 API

| 接口 | 说明 |
|---|---|
| `POST /api/material-agent/tasks/pilot/default` | 使用当前样例路径创建默认试点任务 |
| `POST /api/material-agent/tasks/pilot` | 使用指定知识文件、模板文件、输出文件创建任务 |
| `GET /api/material-agent/tasks/{task_id}` | 查询任务状态 |
| `POST /api/material-agent/tasks/{task_id}/run` | 执行任务 |

旧同步接口仍保留，但默认关闭：

| 接口 | 说明 |
|---|---|
| `POST /api/material-agent/pilot/run` | 调试用同步执行，生产默认禁用 |
| `POST /api/material-agent/run` | 调试用自定义同步执行，生产默认禁用 |

## 7. 当前工程等级

第二阶段后，项目已具备企业生产服务的任务化雏形：

- 有任务 ID 和状态。
- 有持久化任务记录。
- 有输入/输出文件元数据。
- 有执行指标和错误记录。
- 有任务化 API 和 CLI。
- 有回归测试保障样例不被破坏。

仍未完成的生产能力：

- 数据库任务表和迁移脚本。
- Redis/Celery/RQ 等异步 worker。
- 文件上传、知识库导入、对象存储。
- 鉴权、租户隔离、审计日志、脱敏。
- LangGraph checkpoint、人审节点、重试策略。
- OpenTelemetry、指标、集中日志。

## 8. 第三阶段建议

下一阶段建议做“异步执行与数据库替换准备”：

1. 抽象 `TaskRepository` 协议，为 PostgreSQL 仓储预留实现。
2. 增加 `TaskExecutor`，把任务执行从 API 线程拆出去。
3. 先实现本地后台线程/进程 worker，再切 Redis 队列。
4. 增加任务事件日志：created/running/succeeded/failed。
5. 增加文件指纹、输入输出文件大小、校验和。
