# 物料分类补全样例数据流程关系说明

更新时间：2026-05-18

## 1. 需求目标

物料分类补全智能体面向两类样例数据完成自动化处理：

1. **试点物料 AI 三文件流程**：以 PLM 物料 Excel 作为可检索知识源，以目标模板定义需要补全的标准字段，输出接近样例清洗结果的补全 Excel。
2. **AI 测试文件五步流程**：先根据旧字段标准与新字段标准生成新旧字段映射表，再使用该映射表把旧料号属性值转换成新标准清洗结果表。

该需求不是传统“问答型离线知识库”，更准确地说是**结构化 Excel 知识检索 + 字段映射 + 属性补全 + 人工复核闭环**。

| `10整机-TV成品-TV整机-数据清洗试点_何海珍 20260509.xlsx` | 期望输出样例 | 用于对齐输出格式和字段含义 | 作为验收参照，不直接作为知识源覆盖输出 |

核心处理链路：

1. 读取 PLM Excel，自动识别表头行，清洗空行空列。
2. 过滤有效物料记录，保留 `编号` 或 `旧物料号` 不为空的数据。
3. 读取目标模板的 `主数据标准`，抽取标准字段和必填要求。
4. 通过字段字典、别名、相似字段名把目标字段映射到 PLM 字段。
5. 对可直接补全字段写入结果；对缺失、冲突、低置信度字段进入异常明细。
6. 输出三张工作表：`补全结果`、`异常明细`、`统计`。

## 3. AI 测试文件五步关系

目录：`/Users/yanlongxiang/Documents/Claude/Projects/AI测试文件`

| 步骤 | 文件 | 角色 | 处理逻辑 |
|---:|---|---|---|
| 1 | `第1步：输入1-旧字段标准.xls` | 旧字段标准 | 提取旧字段 `属性分组`、`属性名称` |
| 2 | `第2步：输入2-新字段标准.xls` | 新字段标准 | 提取新字段 `属性分类`、`新属性名称`、`业务定义` |
| 3 | `第3步：根据第1步第2步输出-新旧字段标准映射表.xls` | 映射结果样例/可复用映射表 | 由步骤 1 和 2 生成或人工校正，字段包括 `新属性名称`、`旧属性名称` |
| 4 | `第4步：输入3-旧料号信息.xls` | 待清洗旧料号属性值 | 按旧字段名读取 `属性值` |
| 5 | `第5步：根据第3步输出和第4步输入3输出清洗结果表.xls` | 最终清洗结果样例 | 按映射表把旧属性值转换到新标准字段 |

核心处理链路：

1. 步骤 1 和步骤 2 自动生成候选字段映射。
2. 对同名、包含关系、别名命中的字段自动给出 `映射策略` 与 `置信度`。
3. 低置信度或未命中字段进入人工确认清单。
4. 步骤 4 读取旧料号属性值。
5. 按步骤 3 映射表输出步骤 5 清洗结果表。

## 4. 当前工程实现方式

代码目录：`material_agent/`

| 模块 | 作用 |
|---|---|
| `core/config.py` | 路径、阈值、运行配置 |
| `domain/models.py` | Agent 请求、知识库、目标字段、补全结果等领域模型 |
| `adapters/excel/workbook.py` | Excel 读取、表头识别、工作簿画像、结果写出 |
| `services/knowledge_loader.py` | PLM 知识源加载 |
| `services/template_analyzer.py` | 目标模板解析 |
| `services/field_mapping.py` | 字段映射、别名匹配、映射置信度 |
| `services/completion_engine.py` | 物料补全与五步清洗核心执行 |
| `graph/` | LangGraph 状态、节点、图构建；未安装 LangGraph 时自动 fallback 到线性 Runner |
| `api/` 与 `app/main.py` | FastAPI 服务入口 |
| `cli.py` | 本地验证命令行入口 |

## 6. 后续生产化重点

1. 字段字典从代码迁移到 PostgreSQL 配置表，支持业务人员维护。
2. RAG 检索由结构化字段优先，向量检索只用于字段含义、业务规则、相似描述召回。
3. LangGraph 增加 HITL 节点：低置信度字段、必填缺失、冲突值进入人工确认。
4. 增加审计与脱敏：文件上传、字段映射、模型调用、人工修改全部写入审计表。
5. 离线部署时预下载 wheels、Docker 镜像、模型包，先 CPU 功能验证，再按模型压测结果选择 GPU。
