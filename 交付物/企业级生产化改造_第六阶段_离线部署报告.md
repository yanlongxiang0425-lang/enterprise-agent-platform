# 企业级生产化改造第六阶段：离线部署与发布治理报告

## 本阶段目标

本阶段围绕企业生产项目的离线交付能力、发布治理、运行规范和依赖可复现性继续补齐工程骨架，重点解决以下问题：

- 项目缺少标准离线包构建、安装、验证流程。
- 生产环境缺少 `.env` 模板和 systemd 服务模板。
- 发布前缺少统一验证命令和发布检查清单。
- 本地输出、离线包、缓存目录存在误提交风险。
- Python 版本和二进制依赖未做显式约束，离线安装存在不可复现风险。

## 已完成优化

1. 新增 `Makefile` 标准入口，支持 `make verify`、`make offline-bundle`、样例验证和 Agent 列表检查。
2. 新增 `.dockerignore` 和 `.gitignore` 规则，避免运行产物、离线包、缓存目录进入代码仓库。
3. 新增 `scripts/offline/build_offline_bundle.sh`，用于在联网构建机生成完整离线包。
4. 新增 `scripts/offline/install_offline_bundle.sh`，用于离线服务器从本地 `wheels/` 安装项目。
5. 新增 `scripts/offline/verify_offline_install.sh`，用于离线安装后的启动前验证。
6. 新增 `deploy/offline/env.production.example` 和 `deploy/offline/enterprise-agent-platform.service`。
7. 新增 `docs/offline_deployment.md`、`docs/release_checklist.md`、`docs/operations_runbook.md`、`docs/enterprise_gap_assessment.md`。
8. 修复离线包构建时 Python 3.8 解析依赖失败的问题，构建脚本强制 Python 3.10+。
9. 修复 `uvicorn[standard]` 与 wheelhouse 不一致的问题，将项目运行依赖收敛为基础 `uvicorn`。
10. 修复 `pandas==2.0.3` 与 `numpy 2.x` 的 ABI 不兼容风险，显式锁定 `numpy>=1.24,<2.0`。

## 离线部署方案

联网构建机执行：

```bash
make offline-bundle
```

产物位置：

```text
dist/offline/enterprise-agent-platform-0.4.0/
dist/offline/enterprise-agent-platform-0.4.0.tar.gz
```

离线服务器执行：

```bash
tar -xzf enterprise-agent-platform-0.4.0.tar.gz
cd enterprise-agent-platform-0.4.0
sudo INSTALL_ROOT=/opt/enterprise-agent-platform bash install.sh
sudo INSTALL_ROOT=/opt/enterprise-agent-platform bash verify.sh
```

生产运行方式：

```bash
sudo cp deploy/enterprise-agent-platform.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable enterprise-agent-platform
sudo systemctl start enterprise-agent-platform
```
